# 选区高亮模块

源码目录：`src/highlight/`

选中一段文本后，扩展会把**当前文档里所有相同的片段**一起高亮出来，
并在小地图旁的概览标尺上打上标记，方便快速定位重复出现的片段。

功能思路来自社区扩展 `mde.select-highlight-minimap`，本模块是重写实现，
在它的基础上做了若干改进（见文末）。

## 组成

| 文件 | 职责 |
| --- | --- |
| `index.ts` | 模块入口：注册选区/编辑器/文档事件，暴露 `refresh` 与 `clear` |
| `highlight.ts` | 高亮控制器：匹配全文、创建装饰、清理旧装饰 |
| `options.ts` | 读取面板配置，附带默认值与非法值兜底 |

## 工作流程

1. `onDidChangeTextEditorSelection` 触发后进入防抖（默认 120ms），避免拖动选区时反复重算。
2. 取出选区文本：
   - 选区为空 → 清除高亮；
   - 选区文本为空 → 清除高亮；
   - 选区跨行、长度超过「最大选区长度」，或关闭了「匹配整篇文档」→ 只高亮选区本身；
   - 否则把选区文本按**字面量**转义后做全文正则匹配，命中处全部高亮。
3. 匹配是**大小写敏感**的：`Foo` 与 `foo` 视为不同文本。
4. 装饰通过 `TextEditorDecorationType` 施加：
   - `backgroundColor` —— 编辑器正文里的高亮底色；
   - `overviewRulerColor` + `overviewRulerLane: Full` —— 概览标尺（小地图右侧的竖条）上的标记颜色。
5. 切换编辑器时先清空所有可见编辑器上的旧装饰，避免高亮残留在上一个文件。
6. 文档内容变化后（防抖 200ms）重新计算，匹配位置随编辑保持准确。

## 配置项

全部在管理面板的「选区高亮」分区里编辑，存储在 `context.globalState`，随 Settings Sync 同步。

| Key | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `highlight.enable` | 布尔 | `true` | 是否启用选区高亮 |
| `highlight.backgroundColor` | 颜色 | `#d4d4d4` | 编辑器正文中高亮文字的背景色 |
| `highlight.overviewRulerColor` | 颜色 | `#ff00c7` | 小地图 / 概览标尺上的标记颜色 |
| `highlight.matchWholeDocument` | 布尔 | `true` | 是否匹配选区之外的出现位置 |
| `highlight.maxSelectionLength` | 文本 | `200` | 超过该长度的选区不做全文匹配 |

颜色字段在面板里是**色卡 + 文本框**的组合：色卡给出十六进制色值，文本框可以再手填任意 CSS 颜色
（`#rrggbb`、`rgb()`、`rgba()`、颜色名等）。取值时以文本框为准，文本框留空则用色卡选中的值。

## 命令

| 命令 | 作用 |
| --- | --- |
| `My Extension: Clear Selection Highlight` | 立刻清除当前的高亮 |

面板「选区高亮」分区里的「清除高亮」按钮派发的是同一个动作。

## 相对原扩展的改进

- **装饰类型会被释放**：原扩展每次选区变化都新建装饰类型却不释放，长期使用会累积。
- **有防抖**：原扩展在每次选区变化时同步扫描整篇文档，长文件下容易卡顿。
- **超长与跨行选区不再全文匹配**：避免用几百个字符的片段去正则扫描整篇文档。
- **不会跨文件残留**：切换编辑器时清理所有可见编辑器上的装饰。
- **可关闭、可配置**：增加了开关与「只匹配选区」选项，颜色由面板统一管理。

## 日志

匹配数量变化时会在输出面板记录一条「选区高亮：N 处匹配（文件路径）」。
